This extends the integrated Sana Happy / SD3 Smile CPU prototype (`42ba82f6` per core owner). It changes no canonical core, MOSS sources, model files, queues, services or permissions. Run the **implemented metadata-only command** from this checkout:

It imports no Torch/Diffusers/Transformers class and never opens tensor/checkpoint/tokenizer-binary bodies. Old declared weight checksums are labeled **not freshly verified**: present file sizes plus a prior manifest digest do not prove current payload integrity. All fresh source/config/tokenizer-text checksums, symlink-resolved tensor paths, revisions, file sizes and module origins are in `offline-admission/offline-assets.json`. ## Checkpoint RNG audit proposal: not run against archives

The four exact packets total **2,390,321,324 stat-bytes**. `rng-audit-plan.json` binds their exact paths, sidecar hashes, declared packet digests, logical identities/steps, audit source and save-source pins. `stage-commands.json` freezes exact static command arguments and a restricted-load template requiring the future root-reviewed static-receipt SHA. Neither command is admitted or executed. Placeholder receipt SHA is a missing review output, not a valid runnable value.

`audit_image_checkpoint_rng_pg09.py --mode static` first rechecks each exact packet checksum, lists ZIP members and inspects only bounded `data.pkl` opcodes through `pickletools.genops`. It does not unpickle or read tensor-storage members. It reports GLOBAL references, unresolved STACK_GLOBAL, opcode counts and occurrences of expected field strings. This inventory is not proof of object schema or safe semantics; root must review it before restricted loading. No ZIP extraction occurs.

Only the separately reviewed `--mode rng` uses `torch.load(weights_only=True, map_location='cpu', mmap=True)` without custom globals, unsafe fallback or model/optimizer construction. The allowlisted source schema is exactly `identity,step,trainable,optimizer,torch_rng,python_rng,cuda_rng`. It validates identity/step and emits tensor **shape/dtype** schema plus SHA256 of bounded CPU uint8 RNG fields and a canonical Python RNG tuple. Trainable/optimizer values are not emitted/applied/hashed. RNG is not restored. CUDA stays hidden and must remain uninitialized. Unsupported loading/schema aborts; it does not fall back.

Both modes have a120s wall/CPU ceiling, one thread, at least16GiB MemAvailable before each packet and a hard8GiB address-space limit that is stronger than the requested8GiB RSS cap. That stronger bound can reject this Torch/CUDA-library import before packet loading; root must review and qualify it, not silently relax it. Whole-file checksum IO and retained mmap pages count in the wall/RSS budget. Only tiny synthetic ZIP/tensor packets are exercised in CPU tests; no real archive packet is inspected by these stages in this deliverable.

Source `TrainingState.save` records trainables, optimizer and Torch CPU/Python/CUDA RNG only. Sana step0 is saved after model/optimizer/text/render-context preparation and before diagnostic/render; later saves occur after an optimizer update and before checkpoint diagnostic/render. SD3 step0 follows model/optimizer/training+heldout text preparation and precedes evaluation; later saves are after updates. Source pinning and successful RNG extraction would still not establish the full historical draw stream: runtime/device identity, every intervening random consumer and save/evaluation timing need auditing. Sana's baseline render uses explicit CPU generators but lacks an all-stream save/restore wrapper, so absence of hidden global consumption cannot be assumed. SD3 evaluation saves/restores Torch/Python/CUDA but not NumPy. Archived CUDA RNG bytes require a separate tiny GPU-noise reconstruction admission; CPU seed7 cannot substitute. The exact draw order is source-bound: Sana alternates prompt rows then draws FP32 native CUDA noise at fixedt500; SD3 draws prompt index and1..49 prefix index through CPU `torch.randint`, then native CUDA FP32 noise and BF16 conversion. Matching the later adaptive prefix requires the same learnedG as well as that fixed draw. Text encodings still require native encoders and independent parity checks even if RNG is recovered.

## Sequential native plan and calibration

`sequential-admission-plan.json` freezes stage dependencies, intended input/output schemas, provisional caps, and the future CLI contract. **Native `execution_argv` values are null:** `scripts/run_image_failure_campaigns_pg09.py` and its source-bound reader/lease/guardian/persistence orchestration are not implemented. This makes the implementation gap explicit instead of presenting nonexistent commands as runnable. Root must review a concrete implemented worker/source/input/output manifest before dispatch. The metadata and proposed audit commands above are real implemented entrypoints; the audit still requires separate authorization.

1. After static/RNG source review and a distinct root lease, stage exact local native text conditions and a500-row draw manifest per case. Preserve Sana alternating source prompt policy and fixedt500, SD3 original prompt/index draws and CURRENT-G no-grad prefix. Freeze precise noise bytes, conditions, selected indices/native intervals and source hashes across both public arms. New matched draw assets are a distinct bound experiment unless historical reconstruction is actually proven. Build the complete useful condition table with existing source-bound projections and reject exact collisions of distinct contexts globally before game construction.
2. Replay every archived frozen Off/positive baseline through original native pipelines, actual masks/empty-negative/CFG/sampler and true512px decoder. Check native zero-strength response, teacher arithmetic, scheduler cursor and adapter/CFG branches. Any pixel/endpoint/source mismatch blocks training. No simplified sampler, frozen-prefix substitution or tiny fixture can satisfy this gate.
3. With initial zero adapter only, compute one **training-only** finite positive scalar `sqrt(sum((target-neutral)^2)/total_native_coordinates)` across all500 descriptors in each case; no heldout/fruit values participate. SD3 calibration uses initialG current-prefix semantics. Freeze that scalar, exact calibration row/output hashes, reduction precision/order and final resolved recipe before updates. A zero/nonfinite result blocks rather than adding a fallback/epsilon objective. The scalar remains fixed while later SD3 prefixes/targets change with learnedG. A <=5-update shared-core probe under both presets checks all trainables beforeD, actual D/G movement and lazy fourth-step public penalty. No MSE optimizer or auxiliary loss is added.
4. Measure complete device snapshot/hash/descriptor-condition guard costs, host/GPU peaks and step timings. Sana's148,764,672 FP32 adapter leaves add595,058,688 snapshot bytes plus a full same-sized readback/hash per update; buffer snapshots/readbacks and every-fetch equality checks add costs. Verify the immutable full-state contract under actual native buffers/functional-call behavior. No unqualified incremental shortcut is assumed. Separate-process disk resume must match uninterrupted5 versus2+3 updates for **both** public presets, all selected-row/startG/buffer/prefix/target receipts, losses and complete optimizer/critic/regularizer/RNG state. Actual export/reload and heldout-evaluation RNG preservation are separate gates.

Only after those gates and measured projections fit a root-issued budget, sequentially admit each fixed **1,000G+1,000D/batch2** public `bispf` and `bispf_optimized` arm per case;500descriptors yield2,000exposures/four balanced cycles in each D/G stream. Save0/20/250/500/750/1000 and complete full horizon, then the exact heldout/fruit strengths/seeds/teachers and independent matched image-quality review. Failure stays failure; probe success is not convergence or quality evidence.
