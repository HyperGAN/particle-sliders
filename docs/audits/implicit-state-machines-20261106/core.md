# Shared core lifecycle and execution state-machine audit

Read-only source audit of `origin/main` at `2b212c108637ca996d7676664547056066f2b22c` in `/ml2/particlesliders-working/implicit-state-machines-main-20261106`. No imports, models, training, GPU work, service calls, or tests were run. Paths below are relative to `packages/particle-sliders-core/src/particle_sliders/`.

“Implicit machine” means that previous events alter which action can safely happen next, with state spread across flags, counters, closures, subprocesses, or filesystem receipts. A string enum alone is not sufficient. The PG engine's internal update phases/cursors/RNG are audited separately; this covers their public lifecycle envelope.

## C01. Backend preparation and resource-ownership handoff

**Carriers:** `Backend`, local `binding`/`session`, config/capabilities, factory cleanup callback. **States:** unresolved → contract resolved → allocation-free admission passed → factory owns preparation → returned binding owned by lifecycle → live session; constructor/manifest failure → binding cleanup attempted → exception. **Events/guards:** unique installed entry point; correct backend/type; capability/precision/strength/budget checks; validate/preflight and exact PG source checks precede `prepare`; preparation forks caller RNG; after return, `_session` and factory-source hashing must succeed. Import failures become `BackendUnavailable`. `prepare` itself runs before the common binding-cleanup `try`, so partial preparation failures belong to the factory until it actually returns a binding. This ownership boundary matters whenever a product loads weights or installs hooks before a failing return. Sources: [lifecycle.py:154–210](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L154), `350–361`; response specialization [response.py:90–124](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/response.py#L90), `131–148`.

## C02. Packet opening and session acquisition

**Carriers:** optional `resume`/`artifact`, packet schema/config/manifest, newly created session. **States:** fresh request or packet request → packet verified → native session allocated → fresh / restored training / v1 inference-loaded → returned; post-allocation restore/load failure → close attempted → original error. **Guards:** resume and artifact mutually exclusive; initial kind/config/cohort checks happen before backend construction; full manifest check happens against actual prepared session; no automatic format migration or cohort rebinding. A valid packet is not yet a live session. Sources: [lifecycle.py:364–389](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L364), `418–440`, `615–625`.

## C03. Session usability and terminal close

**Carriers:** `closed`, `inference_only`, game `_failed` and `_export_loaded`, binding resources. **Factored states:** open/trainable; open/inference-only; open/game-disabled after a failed restore rollback; closed. `_training()` rejects closed/inference-only; `_open()` rejects only closed. Training can move a session through multiple update counts without changing these flags. `load_inference` sets inference-only only after successful game load; inference-loaded sessions cannot resume/checkpoint/train. `close()` calls binding cleanup before setting `closed=True`; success makes later close a no-op; failure leaves `closed=False` and allows cleanup retry. Context-manager exit attempts cleanup and preserves the operation error with cleanup notes. This is deliberately retryable cleanup, not an explicit `closing`/`cleanup_failed` state; after partial cleanup an ordinary public call can still pass `_open()`. Sources: [lifecycle.py:515–526](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L515), `554–561`, `701–711`, `754–764`; parallel native-inference form [inference.py:301–309](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/inference.py#L301), `319–360`. Existing tests explicitly pin retry after failed close ([tests/test_lifecycle_restore_failures.py:163–179](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/tests/test_lifecycle_restore_failures.py#L163), `233–253`).

## C04. Per-update native admission transaction

**Carriers:** `binding.before_update`, game snapshot, captured native flags, RNG fork, `allowed`. **States:** ready → snapshot captured → native admission running → admitted → PG update; rejection/exception → game rollback plus native restoration attempted → still-open refusal. Only literal `False` rejects; other returned values admit. On failed admission no PG update is called. Admission is outside `step`'s close-on-training-error block, making rejection retryable. The success path does not roll back callback changes: factories must implement their intended admission side effects carefully. Snapshot/RNG guards alone do not make the successful callback read-only. Sources: [lifecycle.py:563–579](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L563).

## C05. Public train-loop commit and observer boundary

**Carriers:** `game.completed_steps`, fixed `recipe.total_steps`, `last_metrics`, local target, `on_step`. **States:** ready at k → admitted update → PG committed k+1 → metrics copied → optional observer → next update or requested target reached. Stop must be an integer strictly beyond current count and within fixed total; this is continuation of a fixed horizon, not a new schedule. Any `advance` failure closes the session; an `on_step` failure also closes it **after the update already committed**. Callback failure therefore cannot mean “that step never happened.” Returned metrics are copies. Sources: [lifecycle.py:478–492](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L478), `563–600`. The engine's failure flags and actual optimizer commit ordering are separate engine machines.

## C06. Exact training restore with rollback and recovery

**Carriers:** incoming game/EMA/last-metrics packet; `prepared_ema`, `prepared_metrics`; previous live game snapshot or no snapshot; prior failure/export flags; runtime restorers. **States:** packet checked → auxiliary state prepared off to side → game preflight → live game application → commit EMA/metrics → trainable; application failure → rollback attempted → either previous state recovered or game explicitly disabled. If already failed/export-loaded, no resumable rollback packet is taken; failed recovery leaves `_failed=True`. A valid later restore can recover a disabled **open** session. Metadata rejection precedes live load hooks. Game apply failure attempts runtime/native flag restoration even when rollback itself fails; original failure retains rollback/restoration notes. EMA and metrics are published only after game apply succeeds. Sources: [lifecycle.py:622–681](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L622). Ordinary update failure invokes close, so recovering a failed game inside an open session and reopening after an update-induced close are different paths.

## C07. Observation transaction and restoration fanout

**Carriers:** copied network state; original registered-buffer objects/values/nonpersistent sets; module training modes; forked RNG; product observation context; `primary` exception. **States:** capture → seed/eval/no-grad → product observation entered → native evaluate/render → unwind → restore values/registrations/state/values/modes. Both success and failure restore. `_restore_all` attempts every action; when an operation error exists, restoration errors become notes; otherwise it raises the first cleanup error and notes later ones. This is not just `train/eval`: buffer object identity, registration, nonpersistent buffers, and RNG are independent state dimensions. Product context must cover native caches and lazy row fetch/length operations outside the adapter network. Sources: [lifecycle.py:244–295](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L244), `298–318`, `713–752`; native-only consumer [inference.py:319–342](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/inference.py#L319).

**Boundary:** restoration failure does not set session/game failure flags or close either session class. The code attempts broad recovery and raises, but there is no separate marker guaranteeing that a caller who catches the error cannot continue on partially restored native state. Do not confuse successful restoration of modes/buffers with successful restoration of every custom state-dict load hook.

RNG coverage also has a precise boundary: initial `network.state_dict()` capture occurs before entering `fork_rng`, and the final `network.load_state_dict()` restoration occurs after that context exits ([lifecycle.py:258](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L258), `284–295`). A custom state-dict hook that consumes RNG during capture/restoration is outside the fork. Ordinary native observation work is protected; arbitrary state hooks are not covered by that ordering. This is a source-level conditional risk, not an observed RNG divergence.

## C08. Borrowed native module configuration lease

**Carriers:** closure snapshots of checkpoint attributes, per-module `training`, per-parameter `requires_grad`. **States:** caller-owned original → temporarily bound/frozen/checkpoint-configured by product → restore attempted → original; restoration failure remains retryable by invoking closure again. Missing checkpoint attributes are restored by deleting newly added attributes, not setting guessed defaults. Every action is attempted even if one fails. This is distinct from learned weight checkpoint restore. Sources: [lifecycle.py:321–334](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L321), `495–509`.

## C09. Temporary parameter-freeze lease

**Carriers:** original parameter trainability list in `preserve_parameter_flags`. **States:** original flags → body may freeze/unfreeze → finally restore original flags. Exceptions still restore, but the simple restoration loop stops on its first restoration error, unlike `_restore_all`. Source: [_training.py:7–15](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/_training.py#L7).

## C10. Adversarial-connectivity probe and gradient preservation

**Carriers:** autograd graph traversal `pending`/`visited`/`leaves`; leaf gradient references `buffers`. **States:** response accepted as differentiable → reachable leaves captured → gradients temporarily cleared → retained backward probe → all declared parameters must have gradients → original gradient references restored in `finally`. Detached output is refused before backward; disconnected trainable/bank parameters are refused after the probe; retained graph permits the real update afterward. This is a temporal probe with deliberate gradient mutation, not a static predicate. Source: [_training.py:18–50](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/_training.py#L18).

## C11. V1 export and inference-loaded mode transition

**Carriers:** exported adapter state, selection provenance, packet hash; `game._export_loaded`, session `inference_only`. **States:** usable game → export validated/snapshotted → artifact (session remains training-capable); separately, compatible packet → adapter loaded → inference-only session. V1 artifacts retain the full training manifest/config identity even though payload is adapter-only. Load failure does not set inference-only; actual live module mutation/atomicity belongs to the game's export loader. ## C12. Native-only V2 export and admission

No training-factory fallback exists. Failures after binding return invoke its cleanup; failures before return remain factory-owned. ## C16. Resolved execution request and staged-input protocol

**Carriers:** product profile, normalized request, semantic/runtime/reporting digests, target budget, input names/paths/size/hash, materialized config. **States:** raw config/envelope → profile resolved/defaults applied → inputs captured/hash-bound → resolved immutable-semantics receipt → repeated validation/materialization → launchable config. ## C18. Controller subprocess, pipe, and progress coordination

**Carriers:** `child`, reader thread/queue, `stream_closed`, child exit status, `progress`, worker progress JSON, optional reporter, callbacks. **States:** admitted → fresh output/request/config saved → starting marker → reporter ready if configured → child launched → stream/live-process loop → child reaped → native result verified → completed/checkpointed. Reader-thread output and native progress polling advance independently. ## C19. Parent-death and cancellation/reaping protocol

**Carriers:** parent PID, Linux PDEATHSIG, worker/reporter process groups, exception type, `worker_reaped`. **States:** lifetime-bound subprocess → live → SIGINT on controller failure/cancel → wait up to ten seconds → SIGKILL if needed → reaped → terminal failure/cancelled receipt. ## C20. Checkpoint durability/publication frontier

**Carriers:** actual completed step; checkpoint directory, `training.pt`, `checkpoint.json`, `latest.json`; worker-local `final_checkpoint`; controller `seen` and `last_checkpoint`; reporter's independent verified `durable`. **States:** updates in memory → checkpoint tensor saved → hash/step marker saved → latest pointer advanced → discovery callback / verified reporter checkpoint → final checkpoint returned. ## C23. Reporter attachment, journal replay, and recovery

**Carriers:** stable run ID, fresh attempt ID/sequence, file lock, event journal, writer, reconstructed source offset/anchor, observed step, checkpoint frontier, catalog, terminal fingerprint. **States:** detached → run lock acquired → history replayed → new attempt/writer → attached event/publish → ready → repeated scan → terminal/single-pass/signal boundary commit → complete marker → writer close; any exception → failed marker and close attempted. Changed request hash and interrupted journal tail refuse automatic recovery. Sequence resets per attempt, not globally; replay reconstructs data/durability/terminal state from journal. Sources: [execution/reporting.py:167–224](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/reporting.py#L167), `239–248`, `350–377`, `396–403`.

The reporter's `complete` lifecycle state is not synonymous with training completion: a one-pass scan or stop signal writes `complete` with `terminal_observed=False` (`350–366`). Writer-close failure can change reporter state to failed even after complete was written (`372–377`).

## C24. Append-only metric-tail cursor

**Carriers:** selected metric source, byte offset, last-256-byte anchor, complete-line boundary, source-row hash; observed step/latest metrics/throughput. **States:** no source → preferred existing native source selected → wait for complete newline-terminated row → validate scalar/step → emit durable journal row → advance cursor → publish summary. Short/truncated files wait; incomplete last line waits; overlarge row/nonfinite JSON/anchor mismatch refuses. Source remains sticky after selected/recovered. Sources: [execution/reporting.py:74–138](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/reporting.py#L74), `179–183`, `199–208`, `289–307`.

Concrete limits: anchor checks only the 256 bytes immediately preceding the saved offset, not the whole already observed prefix (`119–121`). Positive steps are validated, but monotonicity/duplicate step rejection is not checked before `self.observed=step` (`79–81`, `303`); an out-of-order native log can lower the observer's step even while `durable` remains a maximum. An incomplete final native line is ignored even if a separate terminal result has appeared; terminal completion depends on the durable checkpoint, not requiring every native metric line. These are observer semantics, not evidence of repeated/missing PG updates.

## C25. Reporter metric catalog and summary revisions

**Carriers:** grow-only `catalog`, content-addressed catalog revision, latest scalar map, cumulative measured seconds/throughput, summary JSON. **States:** unseen metric name → definition added → catalog revision published → event references revision → observation summary updated; status-only scan → republish state while retaining canonical metric summary. Recovery unions historical catalog revisions. A telemetry EMA mentioned in `publish` belongs to the external summary and is not model-weight EMA. Sources: [execution/reporting.py:217–237](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/reporting.py#L217), `239–281`, `295–307`.

## C26. Native terminal result versus reporting terminal result

**Carriers:** controller `training_result`, `result.json`, reporter `native_status`, terminal fingerprint, verified durable checkpoint, reporter process exit. **States:** native worker verified → provisional controller completed/checkpointed receipt → reporter observes terminal and commits → graceful reporter exit → reporting metadata added → final success. Completed requires exact target and verified durable target on the reporter path; duplicate terminal enrichment does not emit another event because fingerprint ignores reporting decoration. If the observer fails after training succeeded, controller writes failed **with** preserved `training_status`, completed count, checkpoint and adapter. This is two coupled result machines, not one success boolean. Sources: [execution/local.py:268–306](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/local.py#L268), `308–343`; [execution/reporting.py:161–164](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/reporting.py#L161), `327–339`.

## Static contracts that should not be counted as additional temporal machines

`SessionConfig` JSON identity, `Capabilities`/`ResponseCapabilities`, `InferenceSpec`, recipe validation/locked-shared checks, unique-entry-point registries, and profile qualification values (`native`, `fixture`, `source_only`, `blocked`) are static descriptors/guards. They participate in the machines above but do not themselves transition as a run progresses. A profile's `source_only` is qualification metadata, not a runtime paused state; `_admit` rejects `blocked` and requires explicit dummy for `fixture`, but does not reject `source_only` ([execution/local.py:156–167](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/local.py#L156)). Registry resolvers fail on missing/ambiguous/wrong-contract entries rather than keeping a mutable global connected/disconnected registry ([lifecycle.py:350](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/lifecycle.py#L350), [response.py:131](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/response.py#L131), [inference.py:162](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/inference.py#L162), [execution/request.py:63](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/request.py#L63), [execution/cli.py:35](https://github.com/HyperGAN/particle-sliders/blob/2b212c108637ca996d7676664547056066f2b22c/packages/particle-sliders-core/src/particle_sliders/execution/cli.py#L35)).

## Most consequential interactions

1. A committed optimizer step can precede a failing callback, durable checkpoint, observer event, and final receipt. These counts/frontiers must remain distinct.
2. Session open/closed, game usable/failed/export-loaded, and inference-only are independent flags. Cleanup retry and restore recovery use different paths; neither is an automatic restart.
3. Product hooks are part of common state integrity: preparation owns resources until binding return; successful admission hooks retain their changes; native observation hooks own caches outside the adapter; preflight is not inside the observation rollback.
4. Individual file replacement is atomic; the whole directory is not. Tensor file, completion marker, latest pointer, adapter, manifest and process exit are progressively stronger evidence.
5. Reporting can terminate training and can fail after training completed. Preserve the separate native result instead of interpreting top-level failed as no updates.
6. Main retains an optional weight-EMA/averaged-export machine despite the standing no-EMA instruction. The audit documents it without enabling it or altering historical artifacts.
