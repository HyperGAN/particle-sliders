# Prepared guardian for later audio software phases

`scripts/guarded_audio_next_pg09.py` is a new, stdlib-only root guardian. Importing it launches nothing. No root launch card has been issued and no GPU phase has been admitted. It leaves the completed smoke guardian, admitted audio workers, native sources and all active MOSS files unchanged.

Only two exact scopes are implemented: YuE2 continuation from the accepted full3 checkpoint to the original total20 recipe on physical GPU1, and Music3's full3 versus fresh1+2 software smoke on physical GPU0. Rendering is rejected. Both original MOSS jobs must first have checksum-bound completed3840/evaluated/frozen-base progress receipts; the new guardian cannot use an available card to bypass their priority.

A future root card must use schema `root-audio-next-admission-v1`, status `REVIEWED_PENDING_FRESH_RESOURCES`, a new concrete admission ID, exact phase/GPU UUID/two lease paths, an immutable proposal path/hash, source hashes for this guardian/resource/kernel code, and both completed MOSS evaluation proof paths/hashes. This is a schema description, not a supplied executable card. The proposal remains marked non-dispatchable; root separately binds its admission-ID placeholder and physical GPU after independent review.

The pure validator fixes the native interpreter, worker/supervisor, complete argument set, model/prompt manifests, original20-step recipe, explicit reviewed continuous source profile and serial process count. It rejects fixtures, added flags, whole-site overlays, a changed resume packet, rendering, retries, automatic chaining and the old4GiB running host floor. All actual source/input bytes and49 PG files are rechecked before admission, within the phase compute deadline. New outputs must be absent and on the expected NVMe filesystem.

The guardian holds both existing card leases, checks physical UUID/residents, kernel/power/thermal/disk/GPU memory, and enforces the **8GiB host floor through its outer resource polling** in addition to the unchanged inner worker guard. Startup floors remain YuE2 GPU16GiB/host12GiB and Music3 GPU30GiB/host24GiB. There is one owned process group and at most one CUDA child; Music3 has three serial children. Preflight and compute share720seconds, with up to180seconds reserved for owned-group shutdown. SIGINT/SIGTERM trigger cleanup, and only the owned group is signaled. A supervisor exiting while its CUDA child survives is a failure. The prior historical MSE hold must remain intact.

Terminal checks require exact update counts, actual adapter/critic/bank movement, finite positive bank deltas/gradients, frozen-base/Off/export proofs, and Music3's complete exact comparison receipt. Independent raw checkpoint review remains required after successful execution. Neither a terminal software receipt nor the CPU tests qualify audio semantics.

The CPU suite uses only synthetic dictionaries, temporary JSON files and mocked process-group lookup. It makes no GPU query, imports no native model, dispatches no subprocess and sends no signal. It covers valid scopes, changed arguments/inputs/sources, resource floors, resident ownership, terminal proofs, nonfinite values and incomplete MOSS priority proofs. Actual GPU behavior remains unrun and the guardian needs independent source review plus frozen repaired proposals before any card is considered.
